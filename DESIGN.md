## Problem Statement
Developers hate writing documentation. README files are often missing, incomplete, or copy-pasted from other projects. An AI can analyze actual code and generate accurate, tailored README content including install commands, usage examples, and feature descriptions — saving hours of tedious writing.

## What Makes This Cool
You paste your code, and AI writes your docs. No templates, no blank page. The "whoa" moment: seeing a complete, accurate README appear in seconds from code you just pasted. Developers can ship documentation alongside code, not weeks after.

## Constraints
- Single-page web app, no auth required
- React + TypeScript + Vite (existing stack)
- Tailwind CSS for styling
- Must work with paste-only input (no GitHub integration in this version)
- Must call an AI API (Claude, OpenAI, etc.) for generation

## Premises
1. **Paste-and-go is the right MVP** — no auth friction, works immediately, fastest path to demo. agree/disagree?
2. **A good prompt is the product** — the quality of output depends on how we analyze and describe the code to the AI. agree/disagree?
3. **Markdown output is sufficient** — no rich text editor needed, just a good copy-to-clipboard experience. agree/disagree?
4. **Client-side API calls are acceptable for MVP** — users paste code directly to the AI provider. For v1, we accept this trade-off (privacy, API key exposure). A server-side proxy can come later.

## Approaches Considered

*Effort scale: S = hours, M = half-day, L = full-day+*

### Approach A: Paste-and-Go (Recommended)
  Summary: Single page with code textarea + generate button → markdown README output
  Effort: S (minimal)
  Risk: Low
  Pros:
    - Works immediately, no friction
    - Fastest path to working demo
    - Easy to iterate on prompt quality
  Cons:
    - No persistence — every visit is fresh
    - No history or version control
  Reuses: Route structure in App.tsx can be simplified (auth routes not needed for MVP)

### Approach B: Full App with Auth + History
  Summary: Auth required, save projects, edit and regenerate, history sidebar
  Effort: M
  Risk: Medium
  Pros:
    - Feels like a real product
    - Users can iterate on output
  Cons:
    - Auth adds friction
    - More to build and maintain
  Reuses: AuthContext, existing route structure

### Approach C: GitHub Integration
  Summary: Paste GitHub repo URL → auto-clone and analyze → generate tailored README
  Effort: L
  Risk: High
  Pros:
    - Most impressive demo
    - Most accurate (real file structure)
  Cons:
    - Requires GitHub API or server-side cloning
    - More complex infrastructure
    - Auth + repo access permissions needed
  Reuses: None (new integration needed)

## Recommended Approach
**Approach A: Paste-and-Go** — single page, paste code, get README. Fastest to demo, easiest to validate the core premise (does AI-generated README actually work well?). We can add auth/history later if this proves valuable.

## Open Questions
- Which AI provider to use? (Claude API, OpenAI, local model?)
- How to handle very large codebases? (Token limits)
- Should we support multiple output formats? (Markdown, HTML, plain text)

## Success Criteria
- User can paste code and receive a coherent README in <10 seconds
- Generated README includes: project description, install commands, usage examples, file structure overview
- Markdown output is copy-paste ready for a real README.md
- UI is functional with clear states: empty (prompt to paste), loading (spinner + "Generating..."), success (rendered markdown), error (friendly error message with retry)
- Privacy warning displayed: "Your code is sent to the AI provider. Do not paste proprietary or security-sensitive code."
- Line limit handling: if code exceeds 2000 lines, truncate with a note "Code truncated — results may be incomplete."

## Distribution Plan
This is a web app served locally (dev) or deployed (future). Existing Vite dev server covers local development. For deployment: Vercel, Netlify, or GitHub Pages would work with zero config.

No CI/CD pipeline needed for initial version — `pnpm dev` is the delivery mechanism for now.

## Next Steps
1. **Set up AI API** — use Claude API (best quality for code understanding). Add `VITE_` prefix to API key env var so it's accessible client-side. Display privacy warning before first use.
2. **Build the UI** — single page: code textarea (top), "Generate README" button (middle), markdown output area (bottom). Include copy-to-clipboard button on output.
3. **Craft the prompt** — system prompt should instruct the AI to: detect the tech stack from imports/dependencies, infer project purpose from file names and structure, generate install commands based on detected package manager (pnpm/npm/yarn), write realistic usage examples based on exported functions/components, use appropriate badges and formatting.
4. **Wire it up** — connect UI to AI API. Handle: loading state (disable button, show spinner), error state (API failure, timeout, rate limit — show retry button), empty state (before first paste), token limit (check line count, truncate with warning if >2000 lines).
5. **Test with real code** — try it on the existing src/ codebase. Iterate on prompt until output is genuinely useful, not just generic.
